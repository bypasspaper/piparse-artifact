# E10 — Serde micro-benchmark: the cost of (de)serialization vs. passthrough (float64 | int64 | int→float | float→int)

**Claim in the paper.** Isolated on a single core at the compiled-but-unoptimised footing (r3: no fnattr/inline/tcb), the
per-field cost of text (de)serialization is dead-stable across K = 1…20 projected fields: float parse ≈ 13 ns/field
(Eisel), float serialize ≈ 22 ns/field (ZMIJ) — serialization dominates (~1.7× the parse); serde ≈ parse + serialize,
slightly SUB-additive (−11 % at K=1 → −2 % at high K); a naive stringstream serializer costs ~4.3× the fast serde. The
no-serde arm (native→native raw-row memcpy) is identical for float64 and int64 (type-independent passthrough anchor);
int (de)serialization is ~1.8× cheaper than float. Mixed-type pipelines (`TOFLOAT64` / `TOINT64` casts) are bounded by their
FLOAT half alone: serde_i2f ≈ pure-float only-serialize at every K; cast+Map itself costs 0–2 ns/row.

**Machine.** Threadripper PRO 5965WX, W1 + 1 io thread, InMemory prefill, `NES_INMEM_REPEAT` 20 (3 for the slow naive
arms — reported throughput is per pass, TRUE = × repeat; the tidy CSVs carry the corrected `mrows_s_true`). Binaries:
float + int panels `f6a7b98343` + overlay (2026-08-27/28); mixed panels `b5d757c9f6` + overlay incl. the TOFLOAT64/TOINT64
plugins (2026-09-03). Everything is in engine tag `piparse-artifact-v1`.

**Measured with** (pbench tag `piparse-artifact-v1`, copies in `yaml/`): experiments `serde_micro_full` (float),
`serde_micro_int_full`, `serde_micro_mixed_full`, `serde_micro_mixed_naive`; queries `serde_micro/{float,int,i2f,f2i}k{1..20}`
(80 catalog entries, generated by `scripts/generators/gen_*_queries_and_exp.py`).

Arms (the 2×2): no-serde = SystemNative → NATIVE sink; only-deser = CSV (`eager_parse: true`) → NATIVE; only-ser =
SystemNative → JSON; serde = CSV (eager) → JSON; serde-naive = CSV → `JSONUncompiled` + `NES_OUTPUT_CODEC=original`
(stringstream). Fast codecs: EiselFloatF64 / FastINT64 in, ZMIJF64 / to_chars out. y = rows/s because input MB/s is not
comparable across CSV and native encodings (decompose divides by per-arm bytes/row: native K·8, CSV = file bytes / 2 M rows).

```

```
Datasets: `floatbase.csv` = 2 M × 20 float64 uniform [0, 1e5) printed `%.6f` (numpy seed 20260827); `intbase.csv` = int64
uniform [0, 1e9) (seed 20260828); `floatk{K}` / `intk{K}` = first K columns + the packed little-endian `.nes` twin
(`nes-systests/testdata/small/csv_to_binary.py --schema float64,...`). The mixed panels reuse these (i2f reads intk, f2i
reads floatk). Exact sizes: `data/serde_micro_dataset_sizes.csv`.

## Caveats / provenance notes

- Footing is r3 (compiled, default invoke, no fnattr / inline / constant-byte tracing, overload off) by design: r1 cannot
  build the 2×2 (SystemNative is a compiled formatter) and would dirty the deser axis with the interpreted index; r3 is the
  stronger claim (even a fast compiled engine pays ~2× for serde).
- Native arms skip the field indexing CSV arms pay, so the parse-side gap includes CSV indexing (bounded by the two
  cross-checks: serialize native-pair 186 vs csv-pair 174 ns/row geomean; parse 109 vs 95). The no-serde line has ~10 %
  run-to-run noise (fast memcpy arm; cosmetic bumps at K = 9/12/15).
- `NES_INMEM_REPEAT`: 20 for all fast arms and for the float naive arm (hence the 1 h 47 min float run); 3 for the int and
  mixed naive arms. `mrows_s_true` already contains the per-arm repeat factor; the `inmem_repeat` column records it.
- Mixed panels require a worker that contains the `ToFloat64` / `ToInt64` function plugins (in the tag; a stale binary
  fails at submit with FunctionNotImplemented). Correctness systest: `nes-systests/formatter/MixedCastSmoke.test`.
- The mixed `serde_naive` curves collapse onto the pure curve of their OUTPUT type (stringstream writer dominates).
